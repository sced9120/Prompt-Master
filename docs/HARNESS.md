# 하네스 · 스킬과 이 도구 (v3.6)

> 이 문서에 나오는 판 번호(v3.1 ~ v3.8.7)는 2026-10-30 에 v3.0.0 으로 다시 매기기 전의 **옛 번호**입니다. 지금 판은 `CHANGELOG.md` 맨 위를 보세요.

"하네스 엔지니어링"은 모델 자체가 아니라 **모델을 감싸는 틀** — 무엇을 읽히고(문맥), 무엇을 검사하고(검증), 틀리면 어떻게 다시 시키는지(되먹임) — 를 설계하는 일입니다.
"스킬(Agent Skills)"은 그 틀의 한 형태로, 지침을 꾸러미로 나눠 두고 **필요할 때 필요한 것만 꺼내 읽게** 합니다.

이 도구는 구글 시트에서 API 를 부르므로 Claude 앱의 스킬 기능을 그대로 쓸 수는 없지만, **같은 원리를 시트 안에 구현**했습니다.

## 무엇을 했나

| 원리 | 이 도구에서 | 어디 |

| 필요한 지침만 꺼내 쓰기 (progressive disclosure) | 프롬프트를 7칸으로 쪼개 그 활동의 기록종류·교과 규칙만 조립. v3.6: 기록 항목별 **[기재 주의]** 를 그 항목 프롬프트에만 붙임 | `10_Engine.buildPrompt`, `🧩 기록종류` |

## 무엇이 좋아지나

- **기재 금지어가 결과에 덜 남습니다.** 예전에는 [검증]이 표시만 하고 교사가 고쳤습니다. 지금은 걸린 학생만 자동으로 한 번 더 고쳐 쓰게 해, 교사가 손볼 줄이 줄어듭니다.
- **지어내기가 줄어듭니다.** 분량을 "90% 이상 채워라"에서 "자료에 없는 내용으로 채우지 않는다"로 바꾸고, 근거 확인으로 자료에 없는 구절을 찾아 줍니다(2026 기재요령의 허위·과장 확인).
- **비용이 덜 늘어납니다.** 고쳐쓰기는 걸린 학생만, 규칙(시스템 프롬프트)은 처음과 똑같이 보내 회사 쪽 캐시 할인을 그대로 받습니다.
- **해마다 손볼 일이 줄어듭니다.** 새 기재요령은 만든이가 규칙판 하나만 고치면 나눠 준 사본들이 받아 갑니다.
- **키가 없어도 같은 틀을 씁니다.** 복사·붙여넣기로 받은 답도 같은 검사·[검증]을 거칩니다.

## 하지 않은 것과 이유

- **모든 학생을 두 번씩 부르는 "생성 → AI 자기 검토"** — 비용이 두 배이고, 금지어·바이트는 규칙 검사가 더 정확합니다. 근거 확인만 선택(기본 꺼짐)으로 두었습니다.
- **시트 안에서 Claude 스킬을 직접 실행** — 스킬은 Claude 앱·Claude Code·코드 실행 도구가 읽는 형식입니다. 시트는 대신 같은 규칙을 조립해 보내고, 내보내기로 스킬을 만들어 줍니다.
- **기재요령 PDF 를 사본이 직접 읽어 금지어를 뽑기** — 해마다 문서 모양이 다르고 오탐 위험이 커서, 사람이 확인한 규칙판을 배포하는 쪽을 택했습니다.
