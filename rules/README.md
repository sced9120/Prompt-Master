# 기재요령 규칙판 (`rules/latest.json`)

사본들은 이 파일을 아래 주소에서 **7일에 한 번** 받아 [📏 기재요령] 시트를 갱신합니다(메뉴 ⑧ [기재요령 규칙 업데이트 확인]으로 바로도).

```
https://raw.githubusercontent.com/sced9120/Prompt-Master/main/rules/latest.json
```

구글 서버(UrlFetchApp)가 받아 가므로 학교망에서 github 가 막혀 있어도 됩니다. 이 파일을 `main` 에 올리는 것만으로 **이미 나눠 준 사본들의 규칙이 바뀝니다**(코드는 안 바뀜).

## 무엇이 바뀌나

| 규칙판 칸 | 사본에서 바뀌는 곳 | 손댄 칸은? |
|---|---|---|
| `rules` | [📏 기재요령] 표의 기본 줄(출처가 "○○ 기재요령"·"맞춤법(기본)") | 출처를 "내 학교"로 적은 줄은 남김 |
| `neisRules` | [📐 공통규칙] NEIS_RULES | 예전 기본 문구 그대로일 때만 바꿈 |
| `byRecord` | [🧩 기록종류] [기재 주의] | 비었거나 직전 판 문구 그대로일 때만 |
| `chars` | [🧩 기록종류] [글자수] | 직전 판·옛 기본값 그대로일 때만 (`history[].chars`) |
| `aiNotice`, `source`, `checked` | [📏 기재요령] 머리말, 버전 정보 | — |

손대서 그대로 둔 칸은 업데이트 알림에 "직접 고친 것 그대로"로 나옵니다.

## 해마다 하는 일 (2~3월, 새 기재요령이 나오면)

1. 교육부·시도교육청의 「학교생활기록부 기재요령 주요 개정사항 안내」를 읽고 바뀐 점을 정리합니다.
   (긴 PDF는 AI에게 "세특·창체·행발에 영향 주는 기재 금지·글자수 변경만 쪽수와 함께 뽑아 줘"라고 시키면 빠릅니다. 결과는 원문과 꼭 대조하세요.)
2. `apps-script/16_Rules.gs` 를 고칩니다.
   - 새 판 객체를 만들고(`RULES_2027`), `id: '2027.1'`, `year`, `checked`, `source`
   - **`history` 에 직전 판(2026)의 `neisRules`·`byRecord`·`chars` 를 넣습니다** — 이것이 있어야 "손대지 않은 칸"을 알아봅니다.
   - 금지어는 `00_Presets.gs` 의 `PRESET_BANNED`(why 에 쪽수), 기록 항목 주의는 `RECORD_RULES_…`
3. `npm test` → `npm run build` (빌드가 `rules/latest.json` 을 코드의 규칙판으로 다시 씁니다) → 커밋 → `main` 에 push.
4. 확인: 사본에서 메뉴 ⑧ [기재요령 규칙 업데이트 확인] → "새 규칙판이 있습니다" → 반영 결과 알림.

같은 해에 고칠 때는 `2026.2` 처럼 뒤 번호만 올립니다. 번호가 커야 사본이 새 판으로 봅니다.

## 지킬 것

- 정규식이 깨지면 그 줄만 빠집니다(사본이 받을 때 검사). 그래도 `npm test` 가 먼저 잡습니다.
- 학생 개인정보·학교 이름을 넣지 마세요. 이 파일은 공개 저장소에 있습니다.
- 규칙판은 보조 장치입니다. "기재 금지 여부의 최종 판단은 교사·학교"라는 안내(`aiNotice`)를 빼지 마세요.
