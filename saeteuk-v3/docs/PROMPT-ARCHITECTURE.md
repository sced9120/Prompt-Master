# 프롬프트 구조

이 문서는 v3가 프롬프트를 어떻게 만드는지 설명합니다. 도구를 고쳐 쓰거나, 왜 이렇게 나왔는지 궁금할 때 보세요.

---

## 한 문장 요약

> 프롬프트는 **쓰는 것**이 아니라 **네 개의 시트에서 조립되는 것**입니다.

---

## 조립 순서

`10_Engine.gs`의 `buildPrompt()`가 다음 순서로 문단을 쌓습니다.

| # | 섹션 | 출처 | 비고 |
|---|---|---|---|
| ① | `# 역할` | 🧩 기록종류 `역할` × 📚 교과영역 `역할 표현` | `{교과}` `{연차}` 치환 |
| ② | `# 과제` | 🧩 기록종류 `목표` + 🗂 활동목록 `활동명`·`활동 개요` | |
| ③ | `# 서술 규칙` | 📐 공통규칙 `WRITING_RULES` | 비어 있으면 생략 |
| ④ | `# 학생부 기재 금지사항` | 📐 공통규칙 `NEIS_RULES` | 비어 있으면 생략 |
| ⑤ | `# 서술 관점과 역량` | 🧩 기록종류 `서술 관점` + 📚 교과영역 `역량·서술 관점` | |
| ⑥ | `# 분량` | 글자수 × 3 = 바이트, 하한 90% 문장 자동 생성 + `BYTE_RULE` | **글자수는 한 곳에서만 관리** |
| ⑦-1 | `# 입력 자료 형식` | 🗂 활동목록 `입력 항목` | 항목이 없으면 생략 |
| ⑦-2 | `# 예시` | `활동명 ▸예시` 시트에서 최대 8개(`EXAMPLE_MAX`) | 결과가 비어 있는 행은 건너뜀 |
| ⑦-3 | `# 성취수준 반영` | 📐 공통규칙 `GRADE_RULE` | 🧩 기록종류 `성취수준 사용`이 켜진 경우만 |
| ⑦-4 | `# 출력` | 📐 공통규칙 `INSTRUCTION` | |

없는 값은 조용히 빠집니다. 동아리 활동에 등급 지침이 섞이거나, 창체에 교과 역량 문구가 들어가는 일이 구조적으로 일어나지 않습니다.

---

## 한 곳에서만 관리되는 것들

v2에서 같은 값이 두 곳에 있어 어긋났던 것들입니다.

| 값 | v3에서의 유일한 출처 | 파급 |
|---|---|---|
| 글자수 | 🧩 기록종류 `글자수` (활동별로 덮어쓰기 가능) | 프롬프트 분량 문장, 검증 한도, 압축 목표 |
| 어미·인칭 규칙 | 📐 공통규칙 `WRITING_RULES` | 모든 활동의 프롬프트 |
| 기재 금지사항 | 📐 공통규칙 `NEIS_RULES` | 모든 활동 + 압축 프롬프트 |
| 교과 역량 | 📚 교과영역 `역량·서술 관점` | 그 교과를 쓰는 모든 활동 |

## 직접 작성 모드

특정 활동만 프롬프트를 통째로 쓰고 싶을 때가 있습니다. `🗂 활동목록`의 `프롬프트 모드`를 **직접작성**으로 바꾸고 I열에 쓰면, 조립을 건너뛰고 그 본문을 쓰되 아래 토큰만 치환합니다.

| 토큰 | 치환 내용 |
|---|---|
| `{ROLE}` | 조립된 역할 문장 |
| `{WRITING_RULES}` | 📐 공통규칙 서술 규칙 |
| `{NEIS_RULES}` | 📐 공통규칙 기재 금지사항 |
| `{BYTE_RULE}` | 바이트 계산법 |
| `{GRADE_RULE}` | 성취수준 지침 |
| `{INSTRUCTION}` | 마무리 지시문 |
| `{COMPETENCY}` | 교과 역량 |
| `{VIEW}` | 기록종류 서술 관점 |
| `{EXAMPLES}` | 예시 시트에서 조립한 예시 묶음 |
| `{CHARS}` `{BYTES}` | 글자수 / 바이트 |
| `{COLUMNS}` | 입력 항목을 `|`로 이은 문자열 |
| `{ACTIVITY}` `{RECORD}` | 활동명 / 기록 항목명 |

정의되지 않은 토큰은 빈 문자열로 사라집니다. 중괄호를 글자 그대로 쓰고 싶다면 직접작성 모드를 피하세요.

## 학생 자료가 들어가는 방식

프롬프트는 시스템 메시지로, 학생 자료는 사용자 메시지로 따로 보냅니다.

```
탐구 주제: 여름철 시간대별 전력 수요와 기온의 관계
주제를 고른 이유: 정전 뉴스를 보고 수요 예측이 궁금해짐
자료와 분석 방법: 전력거래소와 기상청 자료를 시간 단위로 결합
성취수준: 2                       ← 기록종류.성취수준 사용이 켜진 경우만
```

- 빈 칸은 아예 보내지 않습니다.
- **학생 이름은 기본적으로 포함되지 않습니다**(`⚙️ 설정 > 학생 이름 마스킹`).
- 줄바꿈이 섞인 셀은 한 줄로 펴서 보냅니다.

## 예시가 결과에 미치는 영향

예시는 프롬프트에서 가장 무거운 부분이고, 결과를 가장 크게 바꾸는 부분입니다.

**왜 시트에 두고 끌어오는가.** 모델에게 도달하는 최종 문자열만 보면, 예시를 시트에서 읽어 오나 프롬프트 본문에 직접 적어 두나 똑같습니다. 차이는 전부 운영 쪽입니다.

- 예시만 고쳐도 프롬프트 본문은 건드릴 필요가 없습니다. v2에서 프롬프트를 복붙하다 골격이 어긋났던 문제가 재발하지 않습니다.
- 활동을 복제하면 예시가 따라옵니다.
- 예시를 늘리고 줄이는 일이 행 추가/삭제로 끝납니다.
- **예시 자체를 검증할 수 있습니다.** 프롬프트 본문에 박혀 있으면 검증기를 돌릴 대상이 없습니다.
- 예시에 중괄호가 들어가도 토큰 치환기에 걸리지 않습니다. 직접작성 모드에 예시를 적으면 `{...}`가 치환 대상으로 오인될 수 있습니다.

**몇 개가 적당한가.** 1개만 있어도 톤과 구조가 크게 안정됩니다. 3~5개에서 수준별 편차를 다루기 시작하고, 그 이상은 얻는 것보다 매 호출 비용이 더 빨리 늘어납니다. `EXAMPLE_MAX`(기본 8)가 상한입니다.

**무엇을 섞을 것인가.** 같은 수준의 예시만 여러 개 넣으면 모든 학생 결과가 그 수준으로 수렴합니다. 성취수준을 쓰는 기록이면 잘한 경우와 아직 부족한 경우를, 창체라면 주도한 경우와 시행착오를 겪은 경우를 섞으세요. `52_Examples.gs`의 `suggestExamples_()`가 AI에게 요구하는 것도 이 다양성입니다.

**예시는 오염원이기도 합니다.** AI는 예시의 표현을 그대로 따라 씁니다. 예시에 남은 기재 금지 표현은 모든 학생 결과로 번집니다. 그래서 `validateExamples()`가 예시에도 같은 검증기를 돌리고, AI가 만든 예시는 생성 직후 자동으로 검증됩니다.

---

## 검증 규칙

`10_Engine.gs`의 `validateResult()`가 결과를 점검합니다. 패턴은 `00_Presets.gs`의 `PRESET_BANNED`, `PRESET_FORMAT_RULES`에 있습니다.

- `level: 'block'` → `[수정]`. 기재요령상 걸리는 표현.
- `level: 'check'` → `[확인]`. 오탐 가능. 예를 들어 "대회"는 교내 활동 맥락에서 쓸 수 있는 경우가 있습니다.

패턴을 고치려면 `00_Presets.gs`를 직접 수정하세요. 정규식 문자열이므로 특수문자는 이스케이프해야 합니다. 고친 뒤에는 `node test/engine.test.js`로 확인하세요.

검증은 표현만 봅니다. **내용이 사실인지, 그 학생에게 맞는 서술인지는 사람만 판단할 수 있습니다.**

## 압축 프롬프트

`80_Compile.gs`의 `compressPrompt_()`가 따로 만듭니다. 활동별 프롬프트와 구조가 다릅니다.

- 역할과 서술 규칙, 기재 금지사항은 같습니다.
- "내용을 새로 지어내지 않는다. 주어진 문장에 있는 사실만 쓴다"가 핵심 제약입니다.
- 같은 역량이 반복되면 합치고 서로 다른 장면은 살리도록 지시합니다.
- 한도를 넘으면 `trimToBytes()`로 문장 단위에서 잘라 냅니다.

## 테스트

```bash
node test/engine.test.js
```

`00_Presets.gs`와 `10_Engine.gs`는 Apps Script API를 쓰지 않는 순수 자바스크립트여서 Node에서 그대로 돌아갑니다. 테스트는 다음을 확인합니다.

- 바이트 계산이 나이스 기준과 맞는지
- 기록종류마다 프롬프트가 조립되고 미치환 토큰이 남지 않는지
- 동아리·행발에 성취수준 지침이 새어 들어가지 않는지
- 교과 프리셋 전부에서 역할 문장이 깨지지 않는지
- 검증 패턴이 의도한 표현을 잡고, 정규식이 전부 유효한지

프롬프트 규칙을 바꿀 때는 여기에 테스트를 한 줄 더하는 것이 가장 싼 안전장치입니다.
